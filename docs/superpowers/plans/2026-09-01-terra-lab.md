# Terra Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A miner that turns the player's `.tmod` files (plus vanilla) into `data/dataset.json`, and a static Svelte site that solves and browses optimal class loadouts per gamestage from it.

**Architecture:** Pure-JS pipeline (Bun): `.tmod` container → CLR metadata/IL reader → symbolic `SetDefaults` interpreter + recipe/drop scanners → gamestage propagation → JSON. The site loads the JSON, scores items per class, and greedily solves armor set / weapons / accessory slots per stage.

**Tech Stack:** Bun 1.3, Node 22 APIs (`zlib.inflateRawSync`), `hjson` npm package, Svelte 5, Tailwind 4, Vite 8, `@fontsource` fonts, `bun test`.

**Spec:** `docs/superpowers/specs/2026-09-01-terra-lab-design.md`

## Global Constraints

- No git in this project (user request). No commits; skip every "commit" step.
- No .NET SDK available: the CLR reader must be pure JavaScript.
- Light theme, green accents, corner radius ≤ 2px, mono numerals.
- `data/dataset.json` is generated and committed to the folder so `bun run build` never needs the game.
- Tests that need the game installed must skip (not fail) when it is absent.
- Windows paths: tModLoader saves in `%USERPROFILE%/Documents/My Games/Terraria/tModLoader`, Steam in `C:/Program Files (x86)/Steam`.
